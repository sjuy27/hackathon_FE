# 호스트 화면 확인

`src/host_page.png`를 기준으로 기존 모바일 페이지와 같은 글꼴·390:844 프레임을 사용한다. 참고 PNG는 원래 경로에 보존하며 앱 리소스로 사용하거나 Git에 추가하지 않는다. Figma 보조 링크는 접근 권한 오류로 열리지 않았다.

## 화면과 경로

- `/merchant` (별칭 `/host`): 사장님 홈. 진행률, 등록·영상·메뉴 수정 카드, 통계 카드와 홈·가게 정보·지도·통계 하단 메뉴.
- `/merchant/register`: 질문·답변·인식 결과 확인, 녹음·받아쓰기 또는 직접 입력. 현재 단계와 완료 단계를 표시한다.
- `/merchant/review`: 5개 정보 카드, 확인 필요 항목, 수정 폼, 영문 미리보기와 가게 게시.
- `/merchant/video`: 메뉴, 사진 1~5장, 직접 쓴 설명 또는 음성, 미리보기, 예상 길이, 자막 언어와 생성 진행률·완료·실패 재시도.
- 기존 `/merchant/edit`는 기존 가게·메뉴 수정 로직을 재사용한다.

버튼·헤더·분류 칩·사진 슬롯·아이콘은 기존 컴포넌트를 확장한다. 음성 질문 읽기·3초 침묵 감지·중복 전송 방지·음성 확인·번역 재조회·영상 작업 폴링과 실패 시 대체 영상을 재사용한다. 마이크는 사용자가 시작할 때 요청한다.

## 미디어 주소

백엔드 `app/services/views.py`의 `media_url()`은 `/media/...` 또는 `/media/...?v=...`를 반환하며, `app/main.py`가 `/media`를 정적 제공한다. 썸네일은 `thumbnail_url`, 생성 영상은 `video_url`이다. 업로드는 `photos` 필드로 전송한다.

기존 `src/api.js`의 `mediaUrl()` 하나를 모든 이미지 경로에 사용한다. 전체 HTTP(S) URL은 그대로 사용하고, 상대 경로는 `VITE_MEDIA_BASE_URL`을 우선 사용해 해석한다. 별도 미디어 설정이 없으면 API 서버 출처를 사용하며, 상대 API 경로로 운영하는 경우 현재 출처의 `/media` 프록시를 따른다. 외부 출처의 blob URL과 HTTP(S)가 아닌 원격 주소는 허용하지 않는다.

사진 선택 미리보기는 기기 내 object URL로 표시하며 제거·이동할 때 해제한다. URL이 없거나 이미지 로딩에 실패하면 기존 MediaSlot이 같은 크기의 회색 영역을 표시한다. `.env.example`에는 변수명만 있고 실제 `.env`는 Git에서 제외한다.

## PNG와 남는 차이

- 글꼴은 사용자 지시에 따라 앞선 모바일 페이지와 같다. PNG의 기기 상태 표시줄·회색 바깥 캔버스는 포함하지 않는다.
- 가게 이름, 등록 진행률·메뉴·인식 결과는 실제 API 응답에 따라 표시한다. 통계 API가 없어 PNG의 128회·24회 대신 `—`를 표시한다.
- 등록 미리보기 API는 `preview_en`만 제공하므로 중국어·일본어 미리보기는 비활성이다. 현재 영상 자막 API 연결은 영어·중국어를 사용하고 일본어는 비활성이다.
- 사용자 사진·기존 가게 썸네일이 없으면 PNG와 같은 회색 영역이다. 임의의 정적 사진을 추가하지 않는다.
- 예상 영상 길이는 입력한 자막 줄 수로 계산하며, 설명이 없으면 백엔드의 20~30초 생성 기준을 표시한다. 최종 길이는 생성된 영상 데이터에 따른다.
- PNG의 서로 다른 높이의 등록·결과·영상 화면은 동일 모바일 프레임 안에서 스크롤한다. 수정·오류·재시도 조작은 해당 상태에서 표시한다.

## 검증

`npm run build`, `npm run lint`와 Edge의 320px·390px·1440px 화면 폭을 확인한다. 실제 API는 가게 조회만 사용한다. 등록·인식·확인·수정·게시·사진 업로드·영상 생성·메뉴 수정은 브라우저 모의 API로 검증하고 실제 서버 쓰기는 차단한다. 모의 음성 이벤트로 명시적 시작·질문 읽기·3초 침묵 후 1회 전송·화면 이동 정리를 검증한다. 기존 고객 화면 6개의 회귀 검증도 수행한다. 실제 마이크 장치의 녹음·AI 결과·일본어 지원·통계는 이 검증에 포함하지 않는다.
